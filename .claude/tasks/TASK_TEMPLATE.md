## Workflow

`research → implementation → test → security → review → release`

親エージェントが順に依頼し、要件、変更範囲・差分、前工程の結果、未解決事項を引き継ぐ。

1. research：既存実装、影響範囲、依存関係、懸念、推奨方針を調査する。
2. implementation：調査を基に最小限の実装・修正を行う。
3. test：必要なテストを追加・実行し、要求動作・異常系・境界値・回帰を確認する。
4. security：専門監査を行い、重要度・根拠・影響・修正方針を報告する。
5. review：security結果を受け取り、バグ・設計・保守性を独立して確認する。
6. release：最終差分と検証結果、必要な文書、PR説明案、コミット候補、準備可否をまとめる。

Critical / High、要件未達、テスト失敗があれば完了にせず差し戻す。実装修正はimplementation、テスト追加・修正はtestへ戻す。修正後はtest → security → review → releaseを経て解消を確認する。release中の修正にも適用し、古い結果だけで完了としない。
